FAILURE TRIAGE CASEBOOK

Each case is one attempt by a coding agent to fix a GitHub issue. The attempt failed: the agent's patch did not make the upstream tests pass. For each case a reviewer reads the issue, the FAIL_TO_PASS tests taken from the upstream fix, the gold patch (the upstream fix), the agent's patch and a condensed log of what the agent ran. The reviewer then records why the attempt failed, as one JSON object on one line.

Failure classes, in precedence order. When more than one fits, the first one wins.
1. env_broken: the environment stopped the agent before code quality mattered: a missing dependency, a broken install, the package does not import, or a network error or timeout in the sandbox.
2. task_underspecified: a careful engineer could not infer from the issue what the upstream tests check, such as exact names, messages or formats that the issue never mentions.
3. upstream_tests_wrong: the tests check something other than the issue, or reject a reasonable fix.
4. model_failure: the task was fair and the agent's patch is wrong, incomplete, or missing because it ran out of turns.
5. unclear: not enough evidence to decide.

The verdict has three keys. "evidence" quotes the lines of the case that decide the class. "failure_class" is one of the five classes. "confidence" is a number from 0 to 1.
