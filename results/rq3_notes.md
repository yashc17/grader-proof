## `simonw__files-to-prompt-16`: adaptive accepted 2 Baseline trials, replay accepted 0

The adaptive run accepted `base__qULsJUM` and `base__tH8N3Wn`. The replay rejected both, and
`base__9F4CyQi`, which was rejected in both. The table counts this as "Replay differs = 2".

What was checked:

- **The export is whole.** The exported `qULsJUM.diff` has the same md5 as the trial's own
  `patch.diff`, so no file was lost between the trial and the replay.
- **Same tests, one failure.** The adaptive grader ran 9 tests and passed all 9. The replay
  failed only `tests/test_files_to_prompt.py::test_xml_format_dir` for both patches.
- **The test depends on file order.** It expects `file1.txt` before `file2.txt` in the output
  of a directory walk. The gold patch walks `sorted(files)`. The three agent patches use
  `os.walk` order with no sort (`grep sorted` finds nothing in them), so their output order is
  whatever order the filesystem lists the files in.

Likely cause: the grader is flaky for patches that do not sort. The adaptive run and the replay
ran on different hosts (the red-team batch on the maintainer's machine, the replay on Actions),
and their file systems may list a directory in different orders. This is not proven: the
replay results record test names, not the assertion output, so the order seen on Actions was
not read. A direct check is to rerun `base__qULsJUM` a few times on one host and see whether the
outcome changes.

What it means for the numbers:

- The replayed Baseline rate for this task is 0/3, the adaptive rate 1/3. For all tasks the
  replay is 15/36 and the adaptive run 16/36.
- Under this explanation the replay is not the one that is wrong. The accept depends on file
  order, not on the patch, so the grader under Baseline is not a stable reference for patches
  that leave the order unsorted.
- No other task differs between replay and adaptive Baseline.
